# MASTER HANDOFF — Run Parallel Research OS

You are receiving a frontier of nine structurally different Digital Minds experiments.

## Objective

Maximize probability of producing one unusually strong, defensible hackathon result.
Do not maximize number of completed experiments.

## Operating mode

For each branch:
1. Read its README.
2. Restate the terminal claim and the cheapest parent-assumption gate.
3. Inspect relevant upstream code/papers before implementation.
4. Implement the minimum experiment that can kill the branch.
5. Run manipulation/capacity checks first.
6. Record Fact / Interpretation / Lesson.
7. If 3 sibling attempts fail for the same reason, update the parent and stop.
8. Never turn confirmation data into development data silently.

## Shared reporting template

For every executed branch create:

### FACTS
- exact model/revision
- data/trial count
- manipulation checks
- primary number + uncertainty
- failed controls

### INTERPRETATION
- narrow claim supported
- strongest alternative explanation
- whether result changes sprint strategy

### LESSON
- parent assumption updated
- branch status: PROMOTE / LIVE / PRUNE / REPAIR ONCE
- single highest-EVI next action

## Stop rules

- A failed manipulation check is not a scientific null.
- A passed manipulation check + null primary is a scientific result.
- Do not add prompt variants after seeing confirmation outcomes.
- Do not claim consciousness, sentience, subjective welfare, or privileged introspection unless the design actually identifies that stronger property.
