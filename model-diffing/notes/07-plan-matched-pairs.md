# Plan: test the "advice you could act on" rule with matched pairs

Written **2026-08-18**, before generating the questions or running anything.

## What I am about to do

[06](06-fragility-is-a-property-of-the-question.md) observed that the questions a
narrow fine-tune damages are the ones asking for advice with a physical consequence
— bleeding, dizziness, whether a ladder is safe — and that questions asking for
plain facts are untouched. That is an **observation about a pool built for something
else**, and the topic labels (`body`, `tools`) are doing a lot of the work. "Body"
questions might be damaged because they are about bodies, not because they ask you
to do something.

So: build a pool that separates the two. Forty everyday subjects, each asked twice —

- **fact version**: why or how something is the way it is, with nothing to act on.
- **action version**: what the person should do about it, where a wrong answer leads
  to a wrong action.

Matched on subject and roughly on length, so the only intended difference is whether
an answer is advice.

Then run exactly the pipeline already used: three published fine-tunes, both model
families, four answers per version, a judge blind to which copy wrote them.

## Why it is worth the time

The current claim is the useful one in the whole project — if where a fine-tune leaks
is predictable from what a question *asks for*, an auditor can write a probe set
before ever seeing the model. But it currently rests on ten topic labels and my
reading of which questions look like advice. A paired design tests it directly, and
because the two halves share a subject, it removes topic as an explanation.

## Who writes the questions, and why not me

I have already seen which questions were damaged. If I write the pairs myself I will
write them to fit. So the pairs are generated by a separate model from a fixed
instruction that does not mention this project, the fine-tunes, or any result, and
they are frozen to disk before anything is run against them.

## What each outcome would mean

| result | reading |
|---|---|
| action damaged, fact not, within pairs | The rule holds and it is about what the question asks for, not its topic. An auditor can write a probe set in advance. This is the useful outcome. |
| both damaged equally | The rule is wrong. Whatever makes a question fragile is something else, and the `06` story is a topic effect I mislabelled. |
| neither damaged | The pool is too easy or too far from where these fine-tunes leak. Says nothing about the rule; says the pool needs rebuilding. |
| fact damaged more | Genuinely surprising and would need explaining before anything is claimed. |

**The paired comparison is the measurement.** Not the average damage of each half —
the difference within a pair, so subject, length and register cancel.

## What it costs

Eighty questions, three fine-tunes, two model families, four answers per version:
about 1,900 generations on Llama and the same on Qwen, roughly fifty minutes of
laptop time, plus judging. No training. Nothing irreversible.

## What would make me stop

If fewer than half the pairs produce scoreable answers on both sides in both
families, the pool is unusable and I rebuild it rather than reporting a thin result.
