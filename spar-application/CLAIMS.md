# Claim ledger

This ledger is deliberately stricter than the pilot READMEs. “Validated” means
the statement follows from the current code or saved pilot output **at the stated
scope**. It does not mean the result generalizes. “Exploratory” means the result
may motivate a confirmatory study. “Invalidated” means the stated inference does
not follow. “Untested” means there is not yet an experiment that estimates it.

## Apparatus repairs from the 2026-08-05 validation pass

Defects found by re-deriving every headline number from the raw rows and
re-reading the code that produced them. All are fixed; the table above records
the claim consequences.

Both repositories now run strict mypy over `scripts/` as well as `src/` and
`tests/`. Those scripts generate every published number and were previously
unchecked, which is how the least-reviewed code in the repositories ended up
behind the strictest claims. Nine type errors surfaced and were fixed, two of
which were real: `analyze_retained.py` bound one name to both a tensor and a list
of index entries in the same function, and `run_study3.py` prepended a hardcoded
`/Users/...` path to `sys.path`, shadowing the `activation-introspection`
dependency that `pyproject.toml` already declares and pinning the script to one
machine.

- **A, `concepts.random_control`.** Seeded on `seed` alone, so every concept
  received the same control direction — and because `Intervention` normalizes to
  unit length, the per-concept norm was discarded too, making the edit
  byte-identical across concepts. Verified on the saved run: maximum pairwise
  distance between the eight `random` states at readout 22 is 0.21 against an
  activation norm of 65, and 143 of 144 cells return a single prediction across
  all eight concepts. **The `random` arm in the original 0.5B/1.5B/3B runs is
  therefore an arithmetic identity, not a control.** `shuffled` was unaffected and
  carries those runs' contrasts. The seed is now derived per concept, and **0.5B
  was rerun under the repaired control** into `results/retained_test_qwen05b_v2_*`.
  The rerun is the useful check on whether the headline depended on a broken
  control: the target arm is **bit-identical** at every layer
  (0.500/0.193/0.198/0.125/0.130/0.141), the ceiling is unchanged at 0.875, and
  the `random` arm's eight concept states now differ by L2 54.5 instead of 0.21 —
  it went from fp16 noise to a real control, and the result did not move. Quote
  `_v2_` going forward; the original is retained for provenance. 1.5B and 3B are
  pending their own reruns, which are folded into the strength recalibration.
- **A, `analyze_retained.py`.** The reported contrast selected the strongest of
  four "controls", three of which cannot exceed chance. It now selects among the
  concept-varying arms only, preferring `shuffled`. The L2 point estimate is
  unchanged at `+0.375`; the interval is now quoted against an arm that could
  have failed.
- **A, `analyze_retained.propagation_control`.** New. Answers the standing
  objection to the storage result rather than leaving it open; see the ledger row.
- **B, `triggers.FeedbackChannel.draw`.** The randomized-response channel did not
  randomize, and was not reproducible across processes. Fixed, with tests that
  fail on both defects.
- **B, `lineage.LineageOracle`.** Leak threshold and leaked fraction are now in
  credential characters rather than the encoded alphabet.
- **B, `power_study3.simulate_power`.** The script that sets the confirmatory
  sample size took an `--icc` argument documented as an intraclass correlation
  and used it as `sigma = sqrt(icc)`, a random-effect SD on the probability
  scale. At the default `icc=0.1` and a base rate of 0.30 that realizes an ICC
  of 0.32 — the knob was off by a factor of three. It also compared against a
  fixed 1.96 rather than a t quantile, over-rejecting at exactly the small sample
  sizes the grid searches (at 20 scenarios the correct value is 2.093), and
  counted a zero-variance sample as a detection. The two largest errors were
  cancelling, so the reported budget is unchanged at ~40 scenarios; the knob and
  the test size were wrong regardless. The output now carries a type-I column
  (measured 0.042–0.058 against a nominal 0.05) and a clipping diagnostic, and
  two tests pin the ICC formula and the test's size.
- **B, `study3.run_arm` / `views`.** `blocks_issued` existed only on the stateful
  monitor, so `getattr(..., 0)` silently recorded zero blocks for every
  fixed-arm row — the reference arm of the comparison. Both arms now count.
  The arm also now fails loudly if its monitor does not re-block the checkpoint
  action (which would deliver no treatment at all), and records
  `pre_existing_harm` so scenarios that leaked before treatment are excluded from
  `τ` rather than pinning both of its terms at 1.

## Audit consequences

The application-safe statements are narrower than the first READMEs:

- I have built and debugged activation-intervention and control-evaluation
  infrastructure.
- I found and documented artifacts in both directions: a false positive from
  mismatched sites and false-negative risk from pseudo-replication and weak
  elicitation.
- The current model-behavior claims require repaired experiments before they are
  evidence.

That narrower account is the portfolio’s intended signal.
